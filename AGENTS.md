## Verified Commands

**Frontend** (run from `src/frontend/`):

- **install**: `pnpm install --prefer-offline`
- **typecheck**: `pnpm typecheck`
- **lint fix**: `pnpm fix`
- **build**: `pnpm build`

**Backend** (run from `src/backend/`):

- **install**: `mops install`
- **typecheck**: `mops check --fix`
- **build**: `mops build`

**Backend and frontend integration** (run from root):

- **generate bindings**: `pnpm bindgen` This step is necessary to ensure the frontend can call the backend methods.
- **backend integration tests**: `scripts/test-backend.sh [section ...]` — PocketIC suite in `tests/backend` (keys, outcallAuth, verification, dispatch, tracking, stripe, openai, supportQueue, webhook, orders, pricing, load, scale, upgrade; `pricing` bundles `src/frontend/src/lib/pricing.ts` and checks it against the canister's ledger, tier tables and campaign prices). Tests `src/backend/dist/backend.wasm` (rebuilt first when `mops build` is available).
- **end-to-end**: `scripts/test-e2e.sh` — the real frontend (built with `tests/backend/e2e/bridge.js` in place of the sign-in/actor package: a fixed Ed25519 identity, every actor call recorded on `window.__calls`) in Chromium against the real canister in PocketIC through its HTTP gateway: template → studio text/font/colour edits → reload (draft restored) → saved audience → Step 4 → create → print PDF → upload → test-mode payment → print hand-off (exact multipart, PDF pages and size, address-list XML, job form, submit) → tracking → campaign page. `E2E_LIVE=1` with `C2M_STAGE_USERNAME`/`C2M_STAGE_PASSWORD` and outbound access to `stage-rest.click2mail.com` sends the hand-off, verification and tracking to the print partner's real staging API instead. Output (screenshots, `calls.json`, `print.pdf`) in `tests/backend/.e2e/`.
- **pricing interpreter test**: `moc -r --package core <motoko-core>/src test/pricing.test.mo` — volume tiers, the cost floor, the member rule and `campaignCostCents` in `src/backend/lib/pricing.mo`; prints `pricing: all checks passed`.
- **template audit**: `node tests/templates/run.mjs [--quick]` — builds every gallery template on every format, both orientations and sides, and checks overflow, safe area, USPS zone, #10 windows, tear strips, folds, text overlap, WCAG contrast and the 300 DPI print raster (full run ~6 min, `--quick` the showcase formats only). Exits 1 on any problem.
- **mail-template audit**: `node tests/templates/mail.mjs audit [id-prefix ...]` — builds `tests/templates/mail.html` (the `src/directmail` library converted to studio canvases) and checks every converted template's both sides for the same faults as the template audit plus tiny text (< 6 px) and a dark USPS-zone ground; `FIDELITY=1` also diffs each side against the original React render, `REPORT=<file>` writes JSON; `compare <id> [front|back]` writes a side-by-side PNG, `stats` counts templates per product. `NO_BUILD=1` reuses `tests/templates/dist-mail`.

## Learnings

- Product name is **EZmailout** (EZmailout.com). Printing and mailing run exclusively through the print partner's REST API (Click2Mail, `https://rest.click2mail.com/molpro`); the previous print vendor integration was removed. In the product, only the Admin page names it (see below).
- Provider names (Click2Mail, Stripe, OpenAI / DALL·E / GPT, Resend) appear in the product only on the Admin page, and only to the signed-in admin (`showProviders` in `AdminPage.tsx`: the "You are admin" banner above the integration keys, then the keys, webhook, public config and support inbox cards; the page header is the same for everyone, so it does not shift when admin status arrives); anyone else opening `/admin` — signed out or signed in — gets `NotFoundPage`, the same 404 as an unknown address, so the page does not reveal that it exists (a neutral spinner shows while the session and `getAdminKeys` load), and the header's Admin link is shown only when `useIsAdmin` says the caller is the admin or a controller. `getAdminKeys` tells a non-admin caller nothing but `callerIsAdmin = false`: no admin principal, environment, sandbox switch, webhook path or publishable key (`tests/backend` checks it). Stampy never points anyone to the Admin page: there is no `admin` nav key (frontend `NAV_CHIPS` or `Stampy.navKeys`/prompt), and account or settings questions go to the Dashboard. Everywhere else — storefront, wizard, studio, checkout ("Secure, encrypted checkout"), Stampy (its prompt forbids naming them), toasts, timeline, `index.html`, `project.json` — the wording is neutral ("payment processor", "AI copywriter", "AI backgrounds", "print"). A failed provider call returns `AdminLib.providerError(state, caller, detail, generic)`: the provider's own message only for the admin, because it names the provider and can quote part of a key (`Invalid API key provided: sk_live_****1234`); customers get the neutral `generic`. Text the print partner sends back (error descriptions, outcall failures naming its host, webhook scan text) goes through `Fulfilment.scrub` before it is stored or shown. `tests/backend` checks all of this (customer vs admin errors, scrubbed verification and webhook text). The OpenStreetMap attribution on the radius map stays (its licence requires it), as do "Sign in with Internet Identity" and the footer's caffeine.ai credit.
- White label: apart from the line above and the Admin page, nothing a customer or developer reads names the print partner. UI copy, toasts, backend error and timeline messages, the Stampy prompt, `index.html`, `project.json`, README and code comments say EZmailout, "print" or "print fulfilment" (Admin: "Print fulfilment" section, "Fulfilment API username/password/environment"). Identifiers are neutral too (migration `20261020_000000_FulfilmentNames` renamed the stable fields): `lib/fulfilment.mo` (module `Fulfilment`), `dispatchPrintJob`, `syncPrintTracking`, `verifyAddresses`, `printDocumentId`/`printAddressListId`/`printJobId`, `fulfilmentUsername`/`fulfilmentPassword`/`fulfilmentEnvironment` (`FulfilmentEnvironment`), `PublicConfig.fulfilmentConfigured`. The partner's name remains only where it is fixed elsewhere: its REST URLs, the legacy webhook path `/webhooks/click2mail` (still accepted beside `/webhooks/fulfilment`, `AdminLib.isWebhookPath`, because the partner may be configured to call it), and the immutable history in `migrations/` (file names and old field names). Never rename a past migration.
- Backend stable state is initialised only by the migration chain in `src/backend/migrations` (moc `--enhanced-migration`). Every new stable field needs a new dated migration whose `OldActor` equals the previous `NewActor`; module-level constants inside mixins must be `transient`.
- moc flags promote dot-notation (M0236) and redundant type args (M0223) to errors: call `caller.toText()`, `text.toLower()`, `r.toShared()` etc.; `Int.compare(a, b)` stays explicit.
- Public API stays bindgen-friendly: records with optional fields, payload-less variants, result records `{ ok; error }` — no `Result`, tuples (except the HTTP gateway types) or variants with payloads. The one exception is `_internet_identity_sign_in_finish`, whose type is fixed by the auth provider (see below).
- `src/frontend/src/backend.ts`, `backend.d.ts` and `declarations/` are generated from the compiled candid — never hand-edit.
- Pricing/credit constants live in `src/backend/lib/pricing.mo` + `lib/credits.mo` and are mirrored in `src/frontend/src/lib/pricing.ts` + `lib/credits.ts`; change both.
- Volume tiers: `PricingLib.volumeTiers` (`src/backend/lib/pricing.mo`) and `VOLUME_TIERS` (`lib/pricing.ts`) hold per-piece cents for under 1,000 / from 1,000 / 10,000 / 50,000 pieces (`tierMinimums`/`TIER_MINIMUMS`) on 4.25x6, 6x9, 6x11, letter and 11x8.5_brochure (the competitor's price less 1¢); every other row is flat at `retailPriceCents`, and a tiered row's `retailPriceCents` is its under-1,000 tier. `calculateUnitPrice(row, qty, isMember)` / `getUnitPriceCents(variant, qty, isMember)`: a live member (`AccountLib.isSubscriptionLive`) is priced as at least 10,000 pieces, and a tier at or below `baseCostCents` is lifted to cost + 1¢ (so 4.25x6 at 50k is 56¢, 6x11 74¢, the brochure 108¢ from 1,000). `createCampaign` fixes the unit price and total on the record (`campaignCostCents` refuses an empty order or one over `maxOrderCents`); checkout charges the stored total and refuses a record whose total ≠ unit × count. A campaign holds at most 5,000 recipients, so non-members reach only the first two tiers: "from" prices everywhere (Step 1, catalog bands, gallery, calculator, Stampy) use `startingPriceCents` (the member rate for tiered rows), and `tierSummary` words the reachable tiers. Step 4 prices by recipient count and membership, shows the saving against the under-1,000 price, a member prompt for non-members, and the checkout amount from the canister's `totalCents`; a launched draft is reused only while its price is unchanged. `test/pricing.test.mo` and `scripts/test-backend.sh pricing` check both sides.
- Catalog: `src/frontend/src/lib/catalog.ts` lists the 14 print product families; `lib/pricing.ts` (`ProductSpec`, dollars) and `src/backend/lib/pricing.mo` (cents) hold the 29 authoritative rows and must be changed together. `documentClass` is the exact print product name and `widthInches`/`heightInches` follow that name's order. Legacy keys (`4x6`, `6x18_bifold`, `11x17_trifold`, `8.5x11_perforated`, `multi_page`) are aliased in `PricingLib.normalizeVariant` and `lib/pricing.ts` — never remove the aliases, older campaign records still carry them. `ProductType` keeps `#SelfMailer`/`#SnapPack` for old records; widening a variant used inside a stable `Map` needs an explicit migration (see `migrations/20260922_000000_Click2MailCatalog.mo`) because mutable fields are invariant.
- `ProductSpec.hasAddressBlock` drives the studio's USPS IMb clear zone: true only where the address is printed on the artwork the customer designs, false for envelope-inserted formats (letters, certified letter, priority, reply letter, notecards) where the print partner generates the address page or envelope.
- Mail class: products with several supported classes expose chips in the Step 1 accordion; the pick is stored in `wizard.selectedSpec.mailClass` and sent as the optional `CreateCampaignInput.mailClass`, which `PricingLib.printSpecFor` validates against the row's own classes (`PricingLib.rowMailClasses`, the same rule as the Step 1 chips: only a row that defaults to Marketing Mail may also go First-Class) before it reaches the print job. `StandardMarketing` in the catalog is the wire enum's `#MarketingMail`.
- Brand system (DESIGN.md): Geist / Geist Mono self-hosted in `public/assets/fonts`, indigo `--primary` (#5c5ee8, oklch 0.56; darkened from #6366f1 so white text on it is 4.84:1 and indigo text on the page 4.61:1, both WCAG AA) is the only CTA colour, `--accent` is the pale ice tint (never use `bg-accent` for a CTA), buttons and badges are pills. Print guides are inch-based (`lib/printSpec.ts`: cut 0″, bleed ⅛″ outside the artboard, safe ¼″). Guide labels for the bleed and safe edges sit in the workspace, never on the artwork: "Bleed ⅛″" above the red frame, flush with its right edge (inside the frame the sheet covered it), and "Safe ¼″" under the sheet on the safe line (inside the zone it covered the badge templates put in its top-left corner); `canvas.editor.guide.bleed_label` / `safe_label`, both 9 px screen-size. Emerald works the same way: `--emerald` (#008058) is the fill, deep enough for white text and icons on it, and `.text-emerald-brand` renders `--emerald-ink`, which passes on white and on `bg-emerald-brand/10`–`/15`; a solid amber badge with white text is `amber-700` (amber-500 is 2.2:1); `--destructive` is #e30205 (4.9:1 on white). On a solid `bg-primary` panel, text is full `text-primary-foreground` (never `/70`–`/90`), inner cards darken (`bg-black/10`, not `bg-white/5`, which lightens the indigo under the text) and icons are `text-primary-foreground` (a `text-primary` icon there is invisible). Animated status badges pulse only `motion-safe:`. Text on a pale primary tint (`bg-primary/10`–`/15` badges and notes) uses `text-primary-ink` (`--primary-ink`, ≥ 6:1 in both themes), never `text-primary-foreground`, which is white and meant for the solid `bg-primary` only.
- Consumer surfaces (ripr-style): page `--background` #F6F6F6 / dark #0D0E12, cards #FFFFFF / #16181F; `Card` is `rounded-2xl border-border/60 shadow-soft` (`.shadow-soft` in index.css), feature banners `rounded-3xl`, controls pills. Settings-style content uses `GroupedList`/`GroupedListRow` (`components/ui/grouped-list.tsx`: small-caps title, one rounded card with hairline dividers, icon tile, value, `trailing` controls, chevron on tappable rows). Empty states use `MascotEmptyState` (`components/stampy`) with a pose per context: `mail` (campaigns, scans, rewards), `audience` (presets, recipients), `design`, `checklist` (inboxes); `RewardsBanner` tops the dashboard. `--muted-foreground` stays darker than neutral-500 so small text keeps ≥ 4.5:1 on the #F6F6F6 page.
- Bars are opaque: the sticky header is solid `bg-background`, the tab bar an opaque `bg-card` sheet across the bottom edge, so no text ghosts through a bar. A secondary sticky bar pins under the header at `top-[calc(var(--header-h)+4px+env(safe-area-inset-top,0px))]` (`--header-h` in index.css is the bar, a clamp from 4.5rem to 5.25rem with the viewport, plus the 4 px airmail stripe; never `top-0`, which parks it behind the header), and anything with a large z-index lives in an `isolate` container (the canvas stage holds the selection toolbar's `z-[9500]`) so it scrolls under the header and tab bar. Use theme tokens (`border-border/60`, `bg-muted/60`, `text-muted-foreground`, `shadow-soft`), never hex greys such as `#e5e7eb`/`#f6f7f9`/`#575859`. The studio rail is a 4 × 2 grid on phones and a strip from `sm`; layer rows put the name on its own line above the ordering controls; Step 1 size rows move the price under the name below `sm`.
- Below `lg` the fixed `BottomNav` owns the bottom edge: an edge-to-edge sheet with `rounded-t-[1.75rem]`, five slots (Home, Templates, Create, Campaigns with an unpaid-draft badge, Account; items centred in `max-w-lg`), Create as a raised 56 px indigo `+` button ringed in the card colour (`-mt-9`, accessible name "Create a campaign"), and the active tab marked by a `bg-primary/15` pill behind its icon plus a `text-primary-ink` label; every label sits on one baseline (`justify-end`) and drops to 10 px below 360 px so "Campaigns" fits a 320 px phone; its height including `env(safe-area-inset-bottom)` is `--bottom-nav-h` (0 on desktop, `viewport-fit=cover` in index.html), and the Stampy launcher and panel, toasts, footer padding and `scroll-padding-bottom` are all offset by it — anchor anything new to the bottom the same way. The Stampy launcher is an avatar pill ("Ask Stampy" from `sm`) that counts replies arriving while the panel is closed. The desktop header puts the nav in divided cells (below), with a credits chip and an avatar dropdown (`nav.account.button`; Sign out keeps `nav.sign_out.button`). Brand header (`Layout.tsx`): the logo is Stampy's head (`StampyMark`, the Step 4 pose cropped to `STAMPY_HEAD_VIEWBOX`) in an indigo-ringed disc beside the "EZmailout." wordmark (red stamp dot); the bar is `--header-h` tall with an `.airmail-stripe` (Stampy red + brand indigo) as its bottom edge; the desktop nav is a news-site section bar: full-height cells of the header with hairline dividers (`divide-x` + `border-x`), a bold label and a 20 px indigo mail-themed icon, the active cell tinted (`bg-primary/[0.06]`) with a 3 px indigo underline resting on the airmail stripe (`aria-current="page"`), hover a grey cell with a grey underline; icons (Templates `Palette`, Campaigns `Mailbox`, Dashboard `LayoutDashboard`, Admin `ShieldCheck`, Launch `Send`), labels from `xl` (`sr-only xl:not-sr-only`, so 1024 px fits); the phone menu uses 48 px rows with tinted icon tiles; below `sm` "Sign in" is the fingerprint alone. `StampyPeek` (`components/layout/StampyPeek.tsx`) is Stampy peeking up from behind that stripe, paws on the edge, rising once per load (`.stampy-peek`, still for reduced motion): it is a flex item inside the header row (between the nav and the account controls), never absolutely positioned over the page, so he is on every page and covers nothing; tapping him opens the Stampy panel via `openStampy()` / `OPEN_STAMPY_EVENT` (`lib/stampyChat.ts`). Header sizing is fluid, never breakpoint steps: `--header-h` (72 → 84 px) and `--peek-w` (64 px on phones → 112 px from ~1700 px) are `clamp()`s in index.css, and the peek's mark and paws are sized from `--peek-w` through `.stampy-peek-button/-mark/-paw`, so Stampy grows with the screen without clipping; the logo disc (40 → 52 px) and wordmark (18 → 24 px) use their own clamps. The peek's hover lift only applies under `@media (hover:hover)` (touch shows it at rest; focus-visible still lifts). Every header control is `shrink-0 whitespace-nowrap` and the bar widens to `2xl:max-w-[100rem]`, so nothing wraps at 1920 px.
- Boot screen: `src/frontend/index.html` holds a plain HTML/CSS splash inside `#root` (Stampy's head as inline SVG rendered from `StampyMark` with `boot-` ids, the wordmark, an airmail-stripe progress bar, "Loading EZmailout…"), styled by an inline `<style>` (allowed: `style-src 'unsafe-inline'`; never an inline script, the CSP forbids it). It paints as soon as the HTML and stylesheet arrive and React's first render replaces it. Sizes are `clamp()`s, it honours safe areas and reduced motion, fades in after 150 ms (cached loads never flash it), and after 15 s a CSS-only reveal offers a Reload link (`href=""`, which keeps the deep link) for a stalled bundle; `<noscript>` explains JavaScript is needed. `Geist-latin.woff2` is preloaded. If `StampyMark` changes, regenerate the inline SVG.
- Errors and code splitting: `createRouter({ defaultErrorComponent: RouteErrorPage })` shows a branded "This page hit a snag" page (Try again / Reload / Home, no raw error text) instead of a blank screen. The Step 2 radius map (Leaflet, the largest dependency) is `lazy()`-loaded with a sized loading box; a failed chunk fetch resolves to `RadiusMapUnavailable` (Reload, or use CSV / Saved Presets), never a crash. `vite.config.js` names lazy chunks `assets/index-[name]-[hash].js` so the `.ic-assets.json5` `assets/index-*` immutable rule covers them; a dist swap must `git rm --cached` / `git add -f` every `index-*` file, chunks included.
- Overlays on every screen size: the phone menu closes on Escape and on any path change (not only its own links) and is capped at the space between the header and the tab bar (`overflow-y-auto`), so a landscape phone can reach every row. The Stampy panel is anchored by `top` and `bottom`: its top never goes above the header (+0.75rem) and it is at most 560 px; under `max-height: 500px` it fills the screen down to the tab bar at `z-[60]`, over the header and launcher, so its minimize button stays reachable. Template cards show the hover CTA only under `@media (hover:hover)` (it opens on keyboard focus too and sits at `z-20`, above the preview text); touch screens of any width get the button under the card.
- Loading states never show made-up numbers: `useAccountSync().accountReady` is false until the account record arrives, and the header credits chip, the account menu and `RewardsBanner` show a pulse placeholder until then instead of the store's default 0. While Internet Identity initialises, the header holds a `size-10 sm:w-24` placeholder pill in the controls' place so the peeking Stampy does not jump.
- Pinned bars while scrolling: the header is `sticky top-0` (safe-area inset as padding inside it) and the tab bar `fixed bottom-0 inset-x-0`; nothing between them and the viewport may set `transform`, `filter`, `contain` or an `overflow` other than visible, or sticky/fixed stop tracking the viewport. A page wider than the phone breaks both (the browser widens the layout viewport and content shows beside the header), so measure overflow against the device width: on mobile `innerWidth` grows to fit wide content, which hides the bug from a `scrollWidth > innerWidth` check. Below 360 px the header row uses `px-3` (its controls overran 320 px by under 1 px). While an on-screen keyboard is up (`hooks/use-soft-keyboard.ts`: a text field focused and `visualViewport.height` < 80 % of `innerHeight`; `interactive-widget=resizes-visual` in the viewport meta keeps the layout viewport fixed on Android), the tab bar slides off (`translate-y-[calc(100%+3rem)]`, so the raised Create button goes too; `inert`) and anything with `.hide-with-keyboard` (the Stampy launcher) hides via `html[data-soft-keyboard]`, because iOS stops pinning fixed elements to the screen edge while the keyboard is open.
- Layout presets (`src/frontend/src/lib/layouts.ts`) size every band through `lib/textFit.ts`, never by hand. `textBlockStyle` renders at `line-height: 1.2` with 2px padding on a border-box element, and Geist's glyph content area is taller than 1.2em, so a band budgeted as `fontSize * n` overflows: use `bandHeight(lines, spec)` (it adds the measured glyph spill) and `fitFontSize` to cap a headline at a line count. Blocks stack from the measured height of the block above, so a preset never depends on the artboard's aspect.
- Physical behaviour of each format lives in `src/frontend/src/lib/physical.ts`, keyed off `ProductSpec.layout` (the print partner's production layout) rather than the category (EDDM® pieces are flats on card stock, no crease: every EDDM size is too large to mail folded), and is drawn by `components/canvas/PhysicalOverlay.tsx` in both the 2D artboard and the 3D proof: creases, pressure-seal tear strips, saddle-stitch spine, #10 window cuts and card-vs-paper stock. It is frontend-only presentation — no ledger or candid change, so no migration.
- Canvas orientation: the stored `CanvasState.widthInches/heightInches` are the design as laid out; `orientationOf`/`canvasDims` (`lib/printSpec.ts`) compare them with the product's native size, so rotation adds no field and no candid change. Studio code reads the canvas through `useCanvasDims()` (or `canvasDims(canvas, layout)` outside React) — never `getLayoutDims(selectedLayout)`, which is always native. `rotated` views the whole sheet a quarter turn counter-clockwise: `rotateRect` moves the USPS zone and #10 windows, `physicalTraitsFor(layout, "rotated")` turns creases, tear strips and the spine. The printed piece never changes: `buildPrintPdf` rasterizes each side as laid out and `toNativePage` turns it back onto the native page, so PDFs keep the print partner's size and the zone/folds land where the press puts them. `rotateCanvas` re-lays each side as one group (spacing kept, scaled down uniformly only when it no longer fits, type refit with `countLines`/`bandHeight` so it keeps its line count) and restores the pre-turn canvas exactly while nothing was edited in between (`rotationUndo`). A rotated design shows `OrientationNotice` (#10 window, USPS address zone or envelope).
- List vs detail: `getCampaigns` returns `CampaignSummary` rows (no canvas, no recipients; `toSummary`) for the portal and dashboard (`useCampaigns`); an admin lists every campaign in one reply, so never add the canvas or recipients to the summary. The stored canvas comes only from `getCampaign(id)` (`useCampaign`, detail page) and recipients from `getCampaignRecipients` when a re-run or preset needs them.
- Campaign access goes through `CampaignLib.isOwnedBy` (+ `AdminLib.isAdmin`, which includes controllers). Records migrated from the pre-EZmailout ledger have `ownerId == ""` and are admin-only — never treat an empty owner as "anyone". Every per-campaign query binds `({ caller })` and traps with `CampaignLib.accessDenied`, the same message for an unknown and a foreign id, so ids (sequential `cmp_N`) cannot be probed. `({ caller })` does not change candid.
- `dispatchPrintJob` is guarded by the transient `dispatchInFlight` set, taken before the first `await` and released in `finally` (which also runs when a continuation traps). It is transient on purpose: nothing is in flight across an upgrade, so a persisted flag could only ever strand a campaign. The run sets `#Processing` before suspending and must end in `#Submitted` or `#Failed`; `finally` turns any other end state into `#Failed`.
- Outcall-spending jobs must not be public. The 6-hourly timer in `main.mo` calls the production mixin's *private* `pollActiveCampaigns()` directly — a mixin's private functions are callable from the actor body — while the public `pollActiveTracking` is a controller/admin-only manual trigger. Timers cannot be registered inside a mixin (no `system` capability), so they stay in `main.mo`. Owner-triggered `syncPrintTracking` is rate-limited to one live lookup per campaign per 6 hours (the automatic poll's interval) through the transient `syncCooldowns` map, stamped by every live lookup (owner, admin, timer) and checked before the first `await`; inside the window it returns the stored state with `SyncResult.cached = true`. Once `CampaignLib.trackingFinished` (Delivered, Undeliverable, Returned, or a `#Failed` dispatch) neither owners nor the timer make tracking outcalls; webhooks still record later events. Controllers and the admin bypass both checks.
- Stampy mascot: `src/frontend/src/components/stampy/` holds seven components generated from the source SVGs (C2PA metadata stripped, attributes camel-cased, pixel-identical to the source at 4x). Clip-path/gradient ids are prefixed per instance with `useStampyId()`; pass `title` for an accessible name, omit it for decoration (`aria-hidden`). The thinking avatar's dots sit alone in `.stampy-dots` so the `:nth-of-type` delays in `index.css` count them 1–3.
- Mixins share one actor scope: private functions and `transient` names must be unique across every mixin (a second `clip` in a new mixin is a duplicate-definition error).
- Stampy copilot: there is no `window.caffeine` client; `askStampy` relays through the canister's OpenAI key (signed-in callers, 30 messages/hour, charged before the outcall). The system prompt lives in `lib/stampy.mo`, is never taken from the client, and is built from `PricingLib.rows()` and `Credits`, so it quotes checkout's prices. Replies navigate only through `[[key]]` markers whitelisted in `src/frontend/src/lib/stampyChat.ts` (`NAV_CHIPS`); unknown markers are dropped. When the relay is unavailable the widget answers from `quickAnswer`, built from the same frontend pricing/credit constants — intents are ordered most-specific first because ties go to the earlier one. Before the intents, `quickAnswer` looks up prices from `PRICING_LEDGER`: a size such as `6x9` (either order, 3–14 in; a legacy key such as `4x6` finds its row) gets that format's price (its volume tiers when it has them), or up to five formats cheapest-first when several share it; a product family plus a price word gets the family's starting price. The lookup stands aside for credit questions, membership questions and questions about another topic (tracking, audience, design…) with no price word.
- Support tickets: stable `supportTickets` (migration `20260924_000000_SupportTickets`), filed by `submitSupportTicket` — signed-out visitors allowed, so every field is length-capped, signed-out callers share one hourly bucket, and every caller together is held to 200 tickets an hour. The store holds 5,000: a full inbox drops its oldest ticket (and that ticket's email entry) instead of refusing every new one, and ids continue from the newest ticket's number (`nextTicketNumber`). "Book a demo" files its request the same way (subject "Walkthrough request: …"), falling back to the browser outbox; the outbox is retried on reconnect and every two minutes, and keeps a ticket whose refusal says "try again". Admins read them in the Admin page's Support inbox (`listSupportTickets`, admin-only). The frontend shows the outcome in the timeline's last slot (`DELIVERY_EXCEPTIONS`, amber); anything that places a status on the timeline goes through StatusBadge's `stageIndex`/`isDeliveryException`, never `CAMPAIGN_STAGES.indexOf`, which does not know the exceptions (a returned campaign read "Stage 1 of 5"). `stageIndex` is a slot (both exceptions share the last one), so ordering two statuses uses `STATUS_RANK`, the canister's 0–6 ranking, through `deliveryMoveAllowed`. Adding a case to a variant the API returns is not a Candid subtype (`didc check` reports it); it is safe only because the frontend bindings are regenerated and deployed with the canister.
- Dispatch retries: an owner gets 5 runs per campaign per day, 5 minutes apart (`Limits.admit` on `dispatchRuns`, charged just before the lock); controllers and the admin are not limited. A run that inherits a job id from an earlier run reads `GET /jobs/{id}` first and marks the campaign submitted instead of submitting again when `Fulfilment.jobSubmitted` says so (top-level fields and unambiguous words only: a wrong yes would hide a job that never printed); a submit the print partner refuses as already submitted (`submittedAlready`) also counts as submitted.
- `Limits.admit(windows, budgets, now, windowNs)` admits a call only if every budget has room and then charges them all, so a caller over their own limit never uses up a canister-wide one. `askStampy` uses it for 30 messages/hour per identity and 300/hour for the whole canister. The webhook secret is compared with `Secrets.equal` (`lib/secrets.mo`), which ORs every byte difference with no early exit.
- Production state machine: every `productionStatus` write goes through `CampaignLib.moveProduction`, which applies `productionMoveAllowed`: payment moves AwaitingPayment → ReadyToDispatch; a run goes ReadyToDispatch/Failed → Processing → DocumentUploaded → AddressListReady → JobCreated → Submitted, or to Failed from any step; Submitted is final and nothing returns to the unpaid states. Only the first confirmed payment settles a campaign (`paymentStatus` Unpaid/Pending); a second intent confirmed for the same campaign records a `payment.duplicate` event and changes nothing, so it can neither reopen a submitted campaign nor turn a paid one into test mode. Delivery status moves only through `advanceStatus`, which applies `CampaignLib.deliveryMoveAllowed`: forward by `stageIndex` and only while `productionStatus` is `#Submitted`, so no webhook, poll or admin override can move an unpaid draft or a failed dispatch, and an outcome never goes back to the mail stream. `updateCampaignStatus` returns whether the campaign moved, and the Admin override offers only the stages StatusBadge's `deliveryMoveAllowed` (the frontend mirror) allows. A webhook for a campaign with no `printJobId` is refused; one for a job whose submission is unconfirmed is recorded as "not applied" without moving the timeline. AI endpoints keep a `settled` flag and refund the debit in `finally` if the reply's handling traps.
- Input bounds live in `lib/inputs.mo` (pure, interpreter-tested) and are mirrored in `src/frontend/src/lib/inputLimits.ts`: campaign and preset names 100 characters, every address line (recipient, preset, CSV row, return address) 100, template/preset ids 64, support messages 2,000 (subjects 160). A tracked QR destination must pass `Inputs.redirectUrl` (absolute `http(s)`, dotted host of letters/digits/`.`/`-`/`:port`, no `user@`, printable ASCII without backslashes, ≤ 2,048); `resolveTrackingLink` re-checks stored destinations and falls back to https://ezmailout.com. The frontend normalises with `normalizeRedirectUrl` (adds `https://` to a bare domain; its outputs always pass the canister rule), used by the QR tool's tracked mode, the preflight, Step 4 and `TrackRedirectPage`; static QR codes keep `normalizeDestinationUrl`, which also allows `tel:`, `mailto:` and `sms:`. The stored canvas (`createCampaign`, `saveCanvasState`, which takes unpaid drafts only) must pass `Inputs.canvasError`: 0 < size ≤ 24 in, ≤ 200 layers a side, text boxes ≤ 5,000 characters, ids/colours/fonts ≤ 100, QR destinations ≤ 2,048, captions ≤ 200, image sources `blob:`/`data:image/`/`https://` only and ≤ 1,000,000 image characters over both sides (room for 5,000 recipients in the same 2 MB message). Step 4 sends `canvasForStorage(canvas)` (`lib/inputLimits.ts`), which always passes: it is a preview (the print file is uploaded on its own), so an over-budget image — a cleaned-up AI logo is a PNG data URL of 1 MB or more — is left out of the stored copy, largest first, instead of blocking the order. `product.colorOption` ≤ 64. Admin keys and addresses ≤ 512 (every key rides its outcalls), and the outcall proxy must pass `Inputs.proxyUrl` (https only: every outcall and its credentials go through it). Webhook event text is clipped to 200 characters and provider event ids to 128.

- Text extras (`lib/textStyle.ts`): a text block may carry `letterSpacing` (em), `lineHeight` (× size, default 1.2), `italic` and `rotation` (degrees, about the box centre) — `StudioTextBlock`. They are frontend-only: the editor (`textBlockStyle`, the transform on the element wrapper), the inspector (Spacing, Line height, italic, Turn°; weight 900), `textFit` (`FontSpec`; `widthOf` adds tracking, `bandHeight` uses the leading), `canvas.ts`'s refit and the rasterizer (tracking, leading, italic and rotation drawn on the alphabetic baseline) all read them through `textExtras`/`fontSpecOf`, and `canvasForStorage` strips them (`stripTextExtras`), so candid and the stable state are unchanged (no migration). Any measurement of a text block must go through `fontSpecOf(block)`, never `{ fontSize, fontWeight, fontFamily }` by hand. Preflight measures ink, not boxes: `textInkRect` for the safe area and `textLinesOverlap` (line rects, compared in their own frame when two blocks share a turn) for overlaps; the studio's safe-zone badge uses the same `outOfBoundsIds`. `canvasSignature` includes the extras, so italic or a turn ends a template's pristine state like any other edit. Text wraps through one function, `wrapText` (`lib/textFit.ts`: pre-wrap spaces kept, over-long words broken), used by `countLines` and the rasterizer alike, so the PDF breaks lines where the editor does. Step 4's preflight also fails on text or a QR code in the back's USPS zone (warns on artwork there; `data-ez-bleed`/`data-ez-zone` art is exempt) and on a static QR code with nothing to open; the rasterizer gives a bare domain in a static code `https://`.
