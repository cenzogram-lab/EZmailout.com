## Verified Commands

**Frontend** (run from `src/frontend/`):

- **install**: `pnpm install --prefer-offline`
- **typecheck**: `pnpm typecheck`
- **lint fix**: `pnpm fix`
- **build**: `pnpm build`

**Backend** (run from `src/backend/`):

- **install**: `mops install`
- **typecheck**: `mops check --fix`
- **build**: `mops build`

**Backend and frontend integration** (run from root):

- **generate bindings**: `pnpm bindgen` This step is necessary to ensure the frontend can call the backend methods.
- **backend integration tests**: `scripts/test-backend.sh [section ...]` — PocketIC suite in `tests/backend` (keys, outcallAuth, verification, dispatch, tracking, stripe, openai, supportQueue, webhook, load, scale, upgrade). Tests `src/backend/dist/backend.wasm` (rebuilt first when `mops build` is available).

## Learnings

- Product name is **EZmailout** (EZmailout.com). Printing and mailing run exclusively through the print partner's REST API (Click2Mail, `https://rest.click2mail.com/molpro`); the previous print vendor integration was removed. This line and `lib/fulfilment.mo` are the only places that name the partner.
- White label: apart from the line above, nothing a customer, admin or developer reads names the print partner. UI copy, toasts, backend error and timeline messages, the Stampy prompt, `index.html`, `project.json`, README and code comments say EZmailout, "print" or "print fulfilment" (Admin: "Print fulfilment" section, "Fulfilment API username/password/environment"). Identifiers are neutral too (migration `20261020_000000_FulfilmentNames` renamed the stable fields): `lib/fulfilment.mo` (module `Fulfilment`), `dispatchPrintJob`, `syncPrintTracking`, `verifyAddresses`, `printDocumentId`/`printAddressListId`/`printJobId`, `fulfilmentUsername`/`fulfilmentPassword`/`fulfilmentEnvironment` (`FulfilmentEnvironment`), `PublicConfig.fulfilmentConfigured`. The partner's name remains only where it is fixed elsewhere: its REST URLs, the legacy webhook path `/webhooks/click2mail` (still accepted beside `/webhooks/fulfilment`, `AdminLib.isWebhookPath`, because the partner may be configured to call it), and the immutable history in `migrations/` (file names and old field names). Never rename a past migration.
- Backend stable state is initialised only by the migration chain in `src/backend/migrations` (moc `--enhanced-migration`). Every new stable field needs a new dated migration whose `OldActor` equals the previous `NewActor`; module-level constants inside mixins must be `transient`.
- moc flags promote dot-notation (M0236) and redundant type args (M0223) to errors: call `caller.toText()`, `text.toLower()`, `r.toShared()` etc.; `Int.compare(a, b)` stays explicit.
- Public API stays bindgen-friendly: records with optional fields, payload-less variants, result records `{ ok; error }` — no `Result`, tuples (except the HTTP gateway types) or variants with payloads. The one exception is `_internet_identity_sign_in_finish`, whose type is fixed by the auth provider (see below).
- `src/frontend/src/backend.ts`, `backend.d.ts` and `declarations/` are generated from the compiled candid — never hand-edit.
- Pricing/credit constants live in `src/backend/lib/pricing.mo` + `lib/credits.mo` and are mirrored in `src/frontend/src/lib/pricing.ts` + `lib/credits.ts`; change both.
- Catalog: `src/frontend/src/lib/catalog.ts` lists the 14 print product families; `lib/pricing.ts` (`ProductSpec`, dollars) and `src/backend/lib/pricing.mo` (cents) hold the 29 authoritative rows and must be changed together. `documentClass` is the exact print product name and `widthInches`/`heightInches` follow that name's order. Legacy keys (`4x6`, `6x18_bifold`, `11x17_trifold`, `8.5x11_perforated`, `multi_page`) are aliased in `PricingLib.normalizeVariant` and `lib/pricing.ts` — never remove the aliases, older campaign records still carry them. `ProductType` keeps `#SelfMailer`/`#SnapPack` for old records; widening a variant used inside a stable `Map` needs an explicit migration (see `migrations/20260922_000000_Click2MailCatalog.mo`) because mutable fields are invariant.
- `ProductSpec.hasAddressBlock` drives the studio's USPS IMb clear zone: true only where the address is printed on the artwork the customer designs, false for envelope-inserted formats (letters, certified letter, priority, reply letter, notecards) where the print partner generates the address page or envelope.
- Mail class: products with several supported classes expose chips in the Step 1 accordion; the pick is stored in `wizard.selectedSpec.mailClass` and sent as the optional `CreateCampaignInput.mailClass`, which `PricingLib.printSpecFor` validates against `supportedMailClasses` before it reaches the print job. `StandardMarketing` in the catalog is the wire enum's `#MarketingMail`.
- Brand system (DESIGN.md): Geist / Geist Mono self-hosted in `public/assets/fonts`, indigo `--primary` (#6366f1) is the only CTA colour, `--accent` is the pale ice tint (never use `bg-accent` for a CTA), buttons and badges are pills. Print guides are inch-based (`lib/printSpec.ts`: cut 0″, bleed ⅛″ outside the artboard, safe ¼″). Guide labels for the bleed and safe edges sit in the workspace, never on the artwork: "Bleed ⅛″" above the red frame, flush with its right edge (inside the frame the sheet covered it), and "Safe ¼″" under the sheet on the safe line (inside the zone it covered the badge templates put in its top-left corner); `canvas.editor.guide.bleed_label` / `safe_label`, both 9 px screen-size. Text on a pale primary tint (`bg-primary/10`–`/15` badges and notes) uses `text-primary-ink` (`--primary-ink`, ≥ 6:1 in both themes), never `text-primary-foreground`, which is white and meant for the solid `bg-primary` only.
- Consumer surfaces (ripr-style): page `--background` #F6F6F6 / dark #0D0E12, cards #FFFFFF / #16181F; `Card` is `rounded-2xl border-border/60 shadow-soft` (`.shadow-soft` in index.css), feature banners `rounded-3xl`, controls pills. Settings-style content uses `GroupedList`/`GroupedListRow` (`components/ui/grouped-list.tsx`: small-caps title, one rounded card with hairline dividers, icon tile, value, `trailing` controls, chevron on tappable rows). Empty states use `MascotEmptyState` (`components/stampy`) with a pose per context: `mail` (campaigns, scans, rewards), `audience` (presets, recipients), `design`, `checklist` (inboxes); `RewardsBanner` tops the dashboard. `--muted-foreground` stays darker than neutral-500 so small text keeps ≥ 4.5:1 on the #F6F6F6 page.
- Bars are opaque: the sticky header is solid `bg-background`, the tab bar pill solid `bg-card` over a fade to `--background` that hides the page between the pill and the screen edge, so no text ghosts through a bar. A secondary sticky bar pins under the header at `top-[calc(4rem+env(safe-area-inset-top,0px))]` (never `top-0`, which parks it behind the header), and anything with a large z-index lives in an `isolate` container (the canvas stage holds the selection toolbar's `z-[9500]`) so it scrolls under the header and tab bar. Use theme tokens (`border-border/60`, `bg-muted/60`, `text-muted-foreground`, `shadow-soft`), never hex greys such as `#e5e7eb`/`#f6f7f9`/`#575859`. The studio rail is a 4 × 2 grid on phones and a strip from `sm`; layer rows put the name on its own line above the ordering controls; Step 1 size rows move the price under the name below `sm`.
- Below `lg` the fixed `BottomNav` (Home, Create, Campaigns with an unpaid-draft badge, Account) owns the bottom edge; its height including `env(safe-area-inset-bottom)` is `--bottom-nav-h` (0 on desktop, `viewport-fit=cover` in index.html), and the Stampy launcher and panel, toasts, footer padding and `scroll-padding-bottom` are all offset by it — anchor anything new to the bottom the same way. The Stampy launcher is an avatar pill ("Ask Stampy" from `sm`) that counts replies arriving while the panel is closed. The desktop header groups the nav in one pill, with a credits chip and an avatar dropdown (`nav.account.button`; Sign out keeps `nav.sign_out.button`).
- Layout presets (`src/frontend/src/lib/layouts.ts`) size every band through `lib/textFit.ts`, never by hand. `textBlockStyle` renders at `line-height: 1.2` with 2px padding on a border-box element, and Geist's glyph content area is taller than 1.2em, so a band budgeted as `fontSize * n` overflows: use `bandHeight(lines, spec)` (it adds the measured glyph spill) and `fitFontSize` to cap a headline at a line count. Blocks stack from the measured height of the block above, so a preset never depends on the artboard's aspect.
- Physical behaviour of each format lives in `src/frontend/src/lib/physical.ts`, keyed off `ProductSpec.layout` (the print partner's production layout) rather than the category, and is drawn by `components/canvas/PhysicalOverlay.tsx` in both the 2D artboard and the 3D proof: creases, pressure-seal tear strips, saddle-stitch spine, #10 window cuts and card-vs-paper stock. It is frontend-only presentation — no ledger or candid change, so no migration.
- Canvas orientation: the stored `CanvasState.widthInches/heightInches` are the design as laid out; `orientationOf`/`canvasDims` (`lib/printSpec.ts`) compare them with the product's native size, so rotation adds no field and no candid change. Studio code reads the canvas through `useCanvasDims()` (or `canvasDims(canvas, layout)` outside React) — never `getLayoutDims(selectedLayout)`, which is always native. `rotated` views the whole sheet a quarter turn counter-clockwise: `rotateRect` moves the USPS zone and #10 windows, `physicalTraitsFor(layout, "rotated")` turns creases, tear strips and the spine. The printed piece never changes: `buildPrintPdf` rasterizes each side as laid out and `toNativePage` turns it back onto the native page, so PDFs keep the print partner's size and the zone/folds land where the press puts them. `rotateCanvas` re-lays each side as one group (spacing kept, scaled down uniformly only when it no longer fits, type refit with `countLines`/`bandHeight` so it keeps its line count) and restores the pre-turn canvas exactly while nothing was edited in between (`rotationUndo`). A rotated design shows `OrientationNotice` (#10 window, USPS address zone or envelope).
- List vs detail: `getCampaigns` returns `CampaignSummary` rows (no canvas, no recipients; `toSummary`) for the portal and dashboard (`useCampaigns`); an admin lists every campaign in one reply, so never add the canvas or recipients to the summary. The stored canvas comes only from `getCampaign(id)` (`useCampaign`, detail page) and recipients from `getCampaignRecipients` when a re-run or preset needs them.
- Campaign access goes through `CampaignLib.isOwnedBy` (+ `AdminLib.isAdmin`, which includes controllers). Records migrated from the pre-EZmailout ledger have `ownerId == ""` and are admin-only — never treat an empty owner as "anyone". Every per-campaign query binds `({ caller })` and traps with `CampaignLib.accessDenied`, the same message for an unknown and a foreign id, so ids (sequential `cmp_N`) cannot be probed. `({ caller })` does not change candid.
- `dispatchPrintJob` is guarded by the transient `dispatchInFlight` set, taken before the first `await` and released in `finally` (which also runs when a continuation traps). It is transient on purpose: nothing is in flight across an upgrade, so a persisted flag could only ever strand a campaign. The run sets `#Processing` before suspending and must end in `#Submitted` or `#Failed`; `finally` turns any other end state into `#Failed`.
- Outcall-spending jobs must not be public. The 6-hourly timer in `main.mo` calls the production mixin's *private* `pollActiveCampaigns()` directly — a mixin's private functions are callable from the actor body — while the public `pollActiveTracking` is a controller/admin-only manual trigger. Timers cannot be registered inside a mixin (no `system` capability), so they stay in `main.mo`. Owner-triggered `syncPrintTracking` is rate-limited to one live lookup per campaign per 6 hours (the automatic poll's interval) through the transient `syncCooldowns` map, stamped by every live lookup (owner, admin, timer) and checked before the first `await`; inside the window it returns the stored state with `SyncResult.cached = true`. Once `CampaignLib.trackingFinished` (Delivered, Undeliverable, Returned, or a `#Failed` dispatch) neither owners nor the timer make tracking outcalls; webhooks still record later events. Controllers and the admin bypass both checks.
- Stampy mascot: `src/frontend/src/components/stampy/` holds seven components generated from the source SVGs (C2PA metadata stripped, attributes camel-cased, pixel-identical to the source at 4x). Clip-path/gradient ids are prefixed per instance with `useStampyId()`; pass `title` for an accessible name, omit it for decoration (`aria-hidden`). The thinking avatar's dots sit alone in `.stampy-dots` so the `:nth-of-type` delays in `index.css` count them 1–3.
- Mixins share one actor scope: private functions and `transient` names must be unique across every mixin (a second `clip` in a new mixin is a duplicate-definition error).
- Stampy copilot: there is no `window.caffeine` client; `askStampy` relays through the canister's OpenAI key (signed-in callers, 30 messages/hour, charged before the outcall). The system prompt lives in `lib/stampy.mo`, is never taken from the client, and is built from `PricingLib.rows()` and `Credits`, so it quotes checkout's prices. Replies navigate only through `[[key]]` markers whitelisted in `src/frontend/src/lib/stampyChat.ts` (`NAV_CHIPS`); unknown markers are dropped. When the relay is unavailable the widget answers from `quickAnswer`, built from the same frontend pricing/credit constants — intents are ordered most-specific first because ties go to the earlier one. Before the intents, `quickAnswer` looks up prices from `PRICING_LEDGER`: a size such as `6x9` (either order, 3–14 in) gets that format's price, or up to five formats cheapest-first when several share it; a product family plus a price word gets the family's starting price. The lookup stands aside for credit questions, membership questions and questions about another topic (tracking, audience, design…) with no price word.
- Support tickets: stable `supportTickets` (migration `20260924_000000_SupportTickets`), filed by `submitSupportTicket` — signed-out visitors allowed, so every field is length-capped, the store is capped at 5,000 and signed-out callers share one hourly bucket. Admins read them in the Admin page's Support inbox (`listSupportTickets`, admin-only). A ticket that cannot reach the canister waits in the browser outbox (`ezmailout_support_outbox`) and is re-sent when the backend is reachable; the UI says it was saved on the device, not delivered.
- Unknown paths render `NotFoundPage` through `createRouter({ defaultNotFoundComponent })` in `App.tsx`. TanStack Router v1 has no `*` route (a `path: "*"` route only matches a literal `*`, so every unknown URL showed the router's bare "Not Found"); a catch-all would be `$`.
- Show enums through their label helpers, never raw: `productTypeLabel` (`lib/format.ts`) for `ProductType` and `mailClassLabel` (`lib/pricing.ts`) for `MailClass` (the portal and detail page printed "Eddm" and "MarketingMail").
- Wizard deep links: `/wizard?step=N` goes through `reachableWizardStep`, which opens Step 1 until a mail piece is chosen. Stampy's chips set the step directly and navigate. `WizardLayout` scrolls to the top whenever `currentStep` changes (the effect is keyed on the step, hence its `biome-ignore`), so every step opens on its heading instead of the previous step's scroll position.
- The Stampy launcher owns the bottom-right corner: toasts are offset above it (`Layout.tsx`), `html` has `scroll-padding-bottom: 6rem` and the footer has extra bottom padding, so no button is ever parked under it. Wizard tips (`components/stampy/StampyTip.tsx`) hide for good via `ezmailout_hide_stampy_tips`; the chat menu restores them.
- Support email: when the Resend key and `supportEmailAddress` (admin state, migration `20260925_000000_SupportEmail`) are both set, `submitSupportTicket` stores the ticket and registers a one-shot `Timer.setTimer<system>` that sends it through `lib/resend.mo` in its own message — the caller never waits on Resend and no email failure can roll the ticket back. A shared function body inside a mixin has the `system` capability (a mixin's top level does not). Sends are capped at 60/hour globally, carry an `Idempotency-Key`, and put the customer in `reply_to`; each ticket's outcome is kept in a transient map and shown in the Admin inbox. The sender is `notifications@ezmailout.com`, so that domain must be verified in Resend.
- Outcall transforms: `Http.transform` drops headers and hands the body to the pure `lib/transform.mo` (testable in the interpreter, unlike `lib/http.mo`). An outcall whose success body is only volatile ids passes `transformContext = Http.maskSuccessBody` so a 2xx body is blanked and every replica sees the same response; one whose answer must be agreed on passes `Http.jsonSummary(keys)`, which reduces a 2xx body to those top-level scalars in a fixed order and a non-2xx body to its `message`, so field order, whitespace and request-log ids cannot break consensus.
- Outcall paths are `async*` end to end: `Http.request/get/postText/postBlob`, `syncOne`, `pollActiveCampaigns`, `drainEmailOutbox`, awaited with `await*`. A plain `async` helper (module or private function) is a message the canister sends itself, so each outcall took extra slots in the canister's own queue and a burst of ~300 concurrent requests failed with "could not perform self call" before reaching the network. The only message left is the management-canister call, whose rejection `Http.request` catches (`status = 0`). Never add an `async` helper on an outcall path.
- Support email outbox: stable `supportEmailOutbox` (ticket id → `Support.EmailDelivery`, migration `20261020_000000_FulfilmentNames`). `submitSupportTicket` queues the ticket and drains at once; `main.mo` also drains every 60 s (timers do not survive an upgrade; the outbox does). `drainEmailOutbox` (guarded by transient `drainRunning`) sends due entries oldest first, ≤ 20 per drain and ≤ 60/hour: a send over the hourly cap stays queued for the next hour, no answer / 429 / 5xx is retried after 1 min, 5 min, 30 min, 2 h, 6 h (6 attempts) with the same `Idempotency-Key` (`ezmailout-ticket-<id>`), any other 4xx is final. The admin inbox shows each entry's `lastStatus`; tickets filed before the outbox show no status.
- Stripe budgets (`stripeWindows` in the billing mixin, `Limits.admit`): `createPaymentIntent` 10/hour with a 2 s gap per identity and 1,000/hour canister-wide, charged only once the call will reach Stripe (after the sandbox and free-month paths); `confirmPayment`'s replicated lookup 5 s apart per payment, 30/hour per identity and per payment, 2,000/hour canister-wide. A settled payment is answered before any budget, so a double confirm never shows a wait and never grants twice.
- Address verification is fail-closed end to end: a failed address-list upload, or a failed or error result lookup, marks nothing valid. Only a successful lookup without per-address detail (the list accepted as a whole) passes the locally valid rows.
- Delivery webhooks are idempotent: an `eventId` (or `id`) already recorded for the campaign among the newest 5,000 tracking events is acknowledged with 200 and not recorded again (`recentEventRecorded`).
- The 6-hourly tracking poll takes the 10 in-flight campaigns whose last lookup is oldest (`syncCooldowns`, never looked up first), so with more than 10 in flight every campaign is reached in turn; it used to take the same first 10 by id every run.
- Transient rate maps keyed by caller are swept of finished windows once they pass `Limits.sweepAbove` (2,000 keys): `Limits.admit` sweeps its map and the support mixin's `charge` sweeps its own, so free identities cannot grow memory between upgrades.
- Offline toolchain: when the mops registry is unreachable, moc 1.8.2 from the GitHub release (`motoko-Linux-x86_64-1.8.2.tar.gz`) plus `dfinity/motoko-core` tag `v2.5.0` (its file hashes match `mops.lock`) builds the canister with the `[moc] args` from `mops.toml`, `--release`, `--package core <core>/src` and `--enhanced-migration src/backend/migrations`. The candid it emits must equal `src/backend/dist/backend.did`. `caffeine-bindgen` is not public; when only names change, the generated bindings take the same renames.
- Stripe payment verification (`confirmPayment`) is a *replicated* outcall (`isReplicated = true`, `Http.jsonSummary(Stripe.intentSummaryKeys)`): the subnet agrees on the intent's id, status, amount and currency before any credit or paid status is granted, so one node cannot fake a `succeeded`. `Stripe.parseIntent` reads top-level fields only (`Json.topLevelString`/`topLevelNumber`) — the any-depth `Json.getString` can pick up an embedded charge's `status`. The confirmed intent must match the record's id, amount and `usd`.
- AI credits are charged server-side by the AI endpoints in `mixins/ai-api.mo` (debited before the outcall, refunded on failure); `askStampy` is free and only rate-limited. `deductAiCredits` stays in candid for compatibility but is controller/admin-only; the frontend has no hook for it.
- Asset canister config lives in `src/frontend/public/.ic-assets.json5` (Vite copies it into `dist`; force-add it with the bundle). Only Vite's content-hashed `assets/index-*.js|css` are `immutable`; `index.html`, `env.json` and every other fixed-name file must revalidate, or a deploy strands returning visitors on bundles that no longer exist. Deep links rely on the asset canister serving `/index.html` for unmatched paths. After a deploy, run `scripts/verify-deploy.sh <frontend-host> <backend-canister-id>`. The build minifies with esbuild (`build.minify` in `vite.config.js`, no sourcemaps); `dist` is tracked, so a rebuild must `git rm --cached` the old hashed bundles and `git add -f` the new ones.
- Security headers and the CSP live in the `**/*` rule of `.ic-assets.json5`; the later rules only override `Cache-Control` (headers merge key by key), so every asset and every SPA fallback carries them. Any new browser-side host — a script, `fetch`, image or iframe — must be added to the matching CSP directive first, or it is blocked in production only; list only what the browser itself loads (canister-outcall hosts such as OpenAI, Resend and the print partner stay out). `script-src` has neither `'unsafe-eval'` nor `'unsafe-inline'`: never ship code that evaluates strings (`eval`, `new Function`, string timers), inline `<script>` in `index.html`, `on*=` attributes or `javascript:` URLs (`style-src` keeps `'unsafe-inline'` for React style attributes and Leaflet). Hosts the bundle needs today: the agent's API host (env.json `backend_host`, else `icp0.io`/`ic0.app` when served from a canister domain, else `icp-api.io`; `*.icp0.io` does not cover the bare domain), Stripe (`js.stripe.com`, `*.js.stripe.com`, `hooks.stripe.com`, `api.stripe.com`), OpenStreetMap tiles and Nominatim (radius map), and DALL·E image URLs (shown, and fetched into a blob by the studio). Internet Identity sign-in is a popup to `id.ai` and needs no entry. `Permissions-Policy` keeps `geolocation=(self)` for the radius map's "Use my location". `frame-ancestors 'none'` + `X-Frame-Options: DENY` mean no site can embed the app. `/.well-known/ic-domains` is served as `text/plain` with `Access-Control-Allow-Origin: *`, like `ii-alternative-origins` (JSON). `scripts/verify-deploy.sh` checks the headers after a deploy.
- Custom domains: `src/frontend/public/.well-known/ic-domains` lists `ezmailout.com` and `www.ezmailout.com`, one bare hostname per line (no scheme, no Markdown). The asset canister skips hidden folders, so the `match: ".well-known", ignore: false` rule in `.ic-assets.json5` must stay, or the path falls back to `index.html` and the boundary nodes reject the domain (`verify-deploy.sh` checks for exactly that). DNS records and the boundary-node registration happen outside the repo. Internet Identity principals depend on the origin, so `https://ezmailout.com` is the canonical identity origin: on `ezmailout.com` and `www.ezmailout.com`, `main.tsx` passes `createOptions` from `lib/identityOrigin.ts` (`derivationOrigin: CANONICAL_ORIGIN`, overriding env.json's `ii_derivation_origin`) to `InternetIdentityProvider`, and `public/.well-known/ii-alternative-origins` lists every canonical host except the apex (JSON, `Content-Type: application/json`, `Access-Control-Allow-Origin: *`, max 10 entries). Adding a host means adding it to both `CANONICAL_HOSTS` and that file. Every other host (the canister's `icp0.io` URL, previews, localhost) keeps env.json's value and so signs users in as a different principal. The `createOptions` object is created once at module level — the provider re-creates its AuthClient when it changes.
- Sign-in handshake: `InternetIdentityProvider` (@caffeineai/core-infrastructure) calls three methods on the backend through its own inline IDL, implemented in `mixins/auth-api.mo` with exactly those types: `_internet_identity_sign_in_start : () -> (vec nat8)` (anonymous caller; 32 bytes from `raw_rand`, the nonce II binds into the attribute bundle), `_internet_identity_sign_in_finish : () -> (variant { ok; err : record {} })` and `_initialize_access_control : () -> ()`. Any other signature fails to decode and login errors out, so never change them; check with `didc check backend.did <provider IDL>`. The mixin holds no state. EZmailout reads no II attributes, so `main.tsx` sets `withAttributes={false}` (plain sign-in, users are not asked for their email): login then calls only `_initialize_access_control`; the nonce/`finish` pair stays implemented in case attributes are ever turned on, where `finish` verifies nothing and returns `#ok` for any signed-in caller. `_initialize_access_control` is a no-op: signing in never touches the admin slot.
- Grid columns that can hold a table or other wide content need `min-w-0`: a grid item is at least as wide as its content by default, which widened the Dashboard to 502 px and Step 4 to 462 px on a 390 px phone. A header row that pairs a title with a badge or `whitespace-nowrap` button also needs `flex-wrap`, or its min-content sets the column's width.
- The rasterizer draws text on the alphabetic baseline at the CSS position — line top + (1.2 em − (ascent + descent)) / 2 + ascent, from `measureText().fontBoundingBoxAscent/Descent` — so the PDF matches the editor to a pixel; `textBaseline = "top"` printed every line ~0.15 em high. `sideSignature` keys URLs longer than 512 characters by length and ends, so the pristine check stays cheap with multi-MB image data URLs.
- Floating UI is positioned from its measured size, never a width constant: `SelectionToolbar` measures itself in a layout effect, stays inside the stage's width, sits above the selection or else below it (overhanging a very short stage vertically rather than covering the selection), and folds into two rows with 32 px targets when one row is wider than the stage. The old 392 px estimate was 20 px short and a one-row bar pushed a phone page to 448 px.
- Studio drawer: below `lg` (1024 px) the rail and drawer stack above the artboard, so `Step3DesignCanvas` starts with the drawer closed there (`matchMedia("(min-width: 1024px)")` in the `useState` initialiser) and a rail tab opens it; at `lg` and up it starts open on Templates. An open drawer on a phone pushed the artboard 1,600 px down.
- Studio shapes are SVG data-URL logo layers (`lib/shapes.ts`, `data-ez-shape` marker) — no new canvas schema; templates live in `lib/templates.ts` and are shared by the gallery page and the studio Templates drawer. Shapes use `preserveAspectRatio="none"` and are stretched to their box everywhere (`object-fill` in CanvasEditor, CanvasPreview3D and the campaign thumbnail; `drawImage` to the box in `lib/rasterize.ts`), while uploaded images are fitted inside their box and centred everywhere (`object-contain`, and the rasterizer's contain-fit) — the two used to disagree, which letterboxed a pill into a circle on screen and stretched logos in print. Rounded kinds (`badge`, `rounded`) are drawn for their box's aspect (`shapeUrl(kind, fill, aspect)` puts it in the viewBox) so a pill keeps semicircular ends; `updateLogo` redraws them with `reshapeForBox` whenever a resize changes the aspect, and `recolorShape` keeps a `#rrggbbaa` fill's alpha and the aspect.
- Templates on the canvas: `canvasFromTemplate` lays a template out through `lib/templateLayout.ts`, which depends only on the artboard as laid out and `physicalTraitsFor(layout, orientation)`: `templatePanels` cuts the safe area (less any tear strip, plus ⅛″) into panels at the creases, each ¼″ clear of the fold; the copy goes in the first (top-left) panel, kept off the #10 windows, the QR code in the last and the disc in the top-right one. A tall text panel stacks one column, a wide one (over 1.15:1) puts the copy in a left column. Accent rule, faint accent disc, the overlay word as a pill badge (ink chosen by WCAG contrast), headline (≤ 2 lines, starting size from the column width) and copy, all fitted with `lib/textFit.ts`. The store keeps `templateSignature` (`sideSignature` of the front as the template last laid it out); `isTemplatePristine` compares it with the current front, so any edit — and only an edit — ends it. `rotateCanvas` rebuilds a pristine front natively for the new orientation (the back, which templates never fill, is re-laid as usual), keeps the previous signature in `rotationUndo` for the exact turn-back, and falls back to the group re-layout once the front has been edited.
- Admin role: only a controller writes the admin slot, through `assignAdmin(principal)` (Admin page → "Assign admin", shown when `getAdminKeys().callerIsController`). `saveAdminKeys` requires `AdminLib.isAdmin` (the assigned admin or a controller) and never claims the slot, and `getAdminKeys` shows masked keys to the admin and controllers only.
- Abuse budgets (identities are free to mint, so every per-principal limit has a canister-wide partner). Address verification: 20 calls/hour and 15 s between calls per principal, 300 calls/hour globally, plus the 25,000-address quota, all checked and charged in one message before the first await; the response budget is sized to the batch (32 KB + 1 KB per address, max 1.5 MB). Drafts: at most 5 unpaid campaigns and 10,000 unpaid recipients per principal and 500 unpaid drafts canister-wide (`CampaignLib.maxUnpaidDraftsGlobal`). The canister-wide cap never turns a new draft away while one can make way: once every other check has passed, `createCampaign` calls `makeRoomForDraft`, which sweeps expired drafts and then evicts the draft idle longest (`CampaignLib.oldestIdleDraft` by `lastActivityAt`), skipping any with a confirmed payment or a live checkout opened in the last 24 hours (`evictionProtected`); it refuses only when nothing may be evicted. Per-identity caps still refuse, and a request that fails validation evicts nothing. An unpaid draft expires 14 days after its last activity — its own last update, a staged print file or a checkout opened for it (`CampaignLib.draftExpiresAt`); paid, waived and anything the print partner holds never expire (`isExpirableDraft`). The campaign mixin's private `pruneExpiredDrafts` removes expired drafts with their recipients, staged file and timeline (`removeDrafts`, also used by `deleteCampaignDraft`); it runs on its own 6-hourly timer in `main.mo` and in `createCampaign` before a cap refuses. `confirmPayment` for a draft that no longer exists records the payment as received, grants nothing (no referral month) and tells the customer to contact support for a refund. The portal and detail page show `draftExpiresAt` (`components/campaigns/DraftExpiry.tsx`, `DRAFT_TTL_DAYS` mirrors the TTL). Saved audiences: at most 20 presets and 25,000 addresses per principal; owners free a slot with `deleteCampaignDraft` (unpaid only, refused while a Stripe checkout opened in the last 24 h could still complete). QR scans are counted and logged only for paid campaigns, `code` clipped to 64 and `userAgent` to 128 characters, and each campaign keeps its newest 500 scans (FIFO, trimmed 50 at a time). The pure logic lives in `lib/limits.mo`, which the interpreter can run (`lib/admin.mo` cannot: it imports `lib/http.mo`, which references the management canister).
- Test mode: a campaign paid through sandbox checkout is `#Waived`, exposed as `CampaignRecordShared.testMode` and labelled "Test mode" by `PaymentStatusBadge`. Its print job and tracking always use Staging (`environmentFor`), whatever the admin's environment. Sandbox checkout covers campaign orders only: credit packs and memberships need live Stripe, a sandbox record cannot be confirmed once sandbox mode is off, and sandbox payments never count as a first payment or earn a referral month.
- Print file limit: dispatch posts the whole file to the print partner in one HTTPS outcall (2 MB request cap), so `uploadDocumentChunk` rejects a staged file over 1.9 MB (`maxDocumentBytes`), only accepts PDF/PNG/JPEG, and refuses new uploads once the print partner holds the document. `buildPrintPdf` rasterizes once and steps the JPEG quality down (0.92 → 0.55) until the PDF fits `MAX_PRINT_FILE_BYTES`, and fails before upload, and so before payment, when it never does. The two limits are mirrored; change both.
- Delivery outcomes: `CampaignStatus` ends in `#Delivered`, `#Undeliverable` (includes forwarded mail, which never reached the listed address) or `#Returned` (migration `20260927_000000_ReturnedMail` widened the variant, re-typing every campaign and tracking event). `CampaignLib.stageIndex` ranks them 4 < 5 < 6, so a later return overrides a delivery scan and never the reverse; `statusFromText` tests returned/undeliverable/forward phrases before "deliver" (which "undeliverable" contains), and `Fulfilment.aggregateStage` uses the same mapping and ranking, so a campaign turns Undeliverable or Returned only when at least half of its scans say so. The frontend shows the outcome in the timeline's last slot (`DELIVERY_EXCEPTIONS`, amber); anything that places a status on the timeline goes through StatusBadge's `stageIndex`/`isDeliveryException`, never `CAMPAIGN_STAGES.indexOf`, which does not know the exceptions (a returned campaign read "Stage 1 of 5"). `stageIndex` is a slot (both exceptions share the last one), so ordering two statuses uses `STATUS_RANK`, the canister's 0–6 ranking, through `deliveryMoveAllowed`. Adding a case to a variant the API returns is not a Candid subtype (`didc check` reports it); it is safe only because the frontend bindings are regenerated and deployed with the canister.
- Dispatch retries: an owner gets 5 runs per campaign per day, 5 minutes apart (`Limits.admit` on `dispatchRuns`, charged just before the lock); controllers and the admin are not limited. A run that inherits a job id from an earlier run reads `GET /jobs/{id}` first and marks the campaign submitted instead of submitting again when `Fulfilment.jobSubmitted` says so (top-level fields and unambiguous words only: a wrong yes would hide a job that never printed); a submit the print partner refuses as already submitted (`submittedAlready`) also counts as submitted.
- `Limits.admit(windows, budgets, now, windowNs)` admits a call only if every budget has room and then charges them all, so a caller over their own limit never uses up a canister-wide one. `askStampy` uses it for 30 messages/hour per identity and 300/hour for the whole canister. The webhook secret is compared with `Secrets.equal` (`lib/secrets.mo`), which ORs every byte difference with no early exit.
- Production state machine: every `productionStatus` write goes through `CampaignLib.moveProduction`, which applies `productionMoveAllowed`: payment moves AwaitingPayment → ReadyToDispatch; a run goes ReadyToDispatch/Failed → Processing → DocumentUploaded → AddressListReady → JobCreated → Submitted, or to Failed from any step; Submitted is final and nothing returns to the unpaid states. Only the first confirmed payment settles a campaign (`paymentStatus` Unpaid/Pending); a second intent confirmed for the same campaign records a `payment.duplicate` event and changes nothing, so it can neither reopen a submitted campaign nor turn a paid one into test mode. Delivery status moves only through `advanceStatus`, which applies `CampaignLib.deliveryMoveAllowed`: forward by `stageIndex` and only while `productionStatus` is `#Submitted`, so no webhook, poll or admin override can move an unpaid draft or a failed dispatch, and an outcome never goes back to the mail stream. `updateCampaignStatus` returns whether the campaign moved, and the Admin override offers only the stages StatusBadge's `deliveryMoveAllowed` (the frontend mirror) allows. A webhook for a campaign with no `printJobId` is refused; one for a job whose submission is unconfirmed is recorded as "not applied" without moving the timeline. AI endpoints keep a `settled` flag and refund the debit in `finally` if the reply's handling traps.
- Input bounds live in `lib/inputs.mo` (pure, interpreter-tested) and are mirrored in `src/frontend/src/lib/inputLimits.ts`: campaign and preset names 100 characters, every address line (recipient, preset, CSV row, return address) 100, template/preset ids 64, support messages 2,000 (subjects 160). A tracked QR destination must pass `Inputs.redirectUrl` (absolute `http(s)`, dotted host of letters/digits/`.`/`-`/`:port`, no `user@`, printable ASCII without backslashes, ≤ 2,048); `resolveTrackingLink` re-checks stored destinations and falls back to https://ezmailout.com. The frontend normalises with `normalizeRedirectUrl` (adds `https://` to a bare domain; its outputs always pass the canister rule), used by the QR tool's tracked mode, the preflight, Step 4 and `TrackRedirectPage`; static QR codes keep `normalizeDestinationUrl`, which also allows `tel:`, `mailto:` and `sms:`. The stored canvas (`createCampaign`, `saveCanvasState`, which takes unpaid drafts only) must pass `Inputs.canvasError`: 0 < size ≤ 24 in, ≤ 200 layers a side, text boxes ≤ 5,000 characters, ids/colours/fonts ≤ 100, QR destinations ≤ 2,048, captions ≤ 200, image sources `blob:`/`data:image/`/`https://` only and ≤ 1,000,000 image characters over both sides (room for 5,000 recipients in the same 2 MB message). Step 4 sends `canvasForStorage(canvas)` (`lib/inputLimits.ts`), which always passes: it is a preview (the print file is uploaded on its own), so an over-budget image — a cleaned-up AI logo is a PNG data URL of 1 MB or more — is left out of the stored copy, largest first, instead of blocking the order. `product.colorOption` ≤ 64. Admin keys and addresses ≤ 512 (every key rides its outcalls), and the outcall proxy must pass `Inputs.proxyUrl` (https only: every outcall and its credentials go through it). Webhook event text is clipped to 200 characters and provider event ids to 128.
